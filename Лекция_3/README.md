# Трекер публикаций

Мульти-агентный трекер ищет публикации по заданным темам и составляет короткое резюме. Источники — [archive.org](https://archive.org), [arXiv](https://arxiv.org) и [NUMDAM](https://numdam.org). NUMDAM использует постоянный локальный индекс и ранжирование BM25. Результаты смотрят в панели Streamlit. Письма по умолчанию не отправляются.

Один цикл обработки выглядит так: панель передаёт темы, источники и даты оркестратору, скрапер опрашивает агентов-источники, валидатор отвечает «да» или «нет», суммаризатор возвращает резюме, оркестратор отдаёт результат обратно на панель.

## Схема агентов

Та же страница открывается на вкладке «Схема агентов» в панели. Кнопки Light, Classic, Present, Export и легенда остаются на английском; подписи агентов — на русском. Картинка ниже — это [`diagr/agents.html`](diagr/agents.html); нажатие открывает интерактивную схему.

[![Схема агентов](diagr/agents.png)](diagr/agents.html)

Стрелки на схеме — это данные, которые агент возвращает вызывающему:

| Откуда | Куда | Что передаётся |
| --- | --- | --- |
| Панель | Оркестратор | запуск: темы, источники, диапазон дат |
| Оркестратор | Панель | результат: карточки с резюме |
| Оркестратор | Скрапер | темы и даты |
| Скрапер | Оркестратор | принятые записи |
| Скрапер | Агент archive.org / arXiv | вызов `fetch` |
| Агент-источник | Скрапер | записи: название, ссылка, аннотация; у arXiv ещё авторы и даты |
| Скрапер | Валидатор | одна запись |
| Валидатор | Скрапер | да или нет |
| Оркестратор | Суммаризатор | текст аннотации или страницы |
| Суммаризатор | Оркестратор | резюме |
| Оркестратор | Нотификатор | письмо, если почта включена |

Нотификатор в цикл ничего не возвращает. На схеме это пунктир «почта выкл».

## Как проходит поиск

1. **Панель** (`streamlit_app.py`) или **планировщик** (`main.py`) вызывает `process_items`.
2. **Скрапер** (`scraper.py`) по очереди вызывает `fetch` у каждого подключённого источника. Число `rows` — это лимит на каждый источник, а не на все вместе.
3. Уже виденные идентификаторы отбрасываются, если включён пропуск истории.
4. **Валидатор** (`validator.py`) для archive.org и arXiv оставляет запись, только если в тексте есть все слова хотя бы одной темы. NUMDAM использует OR-поиск BM25 и проверку корректности записи; строгий валидатор к нему не применяется.
5. **Оркестратор** для archive.org и arXiv берёт аннотацию, если в ней не меньше 200 символов, иначе загружает HTML-страницу. NUMDAM всегда использует только аннотацию из API, даже короткую. Статья без аннотации остаётся в выдаче с отметкой о недоступности резюме.
6. **Суммаризатор** (`summarizer.py`) строит резюме через Sumy LSA, Ollama или OpenAI-совместимый провайдер. Sumy работает локально; токенизатор — английский. Поиск BM25 не использует нейросеть и API-ключи. Ошибка суммаризации не убирает найденные статьи из выдачи.
7. При включённой почте **нотификатор** (`notifier.py`) отправляет письмо через SMTP с STARTTLS. В панели кнопка поиска всегда вызывает цикл с `send=False`.

Журнал пишется в терминал и в `main.log` логгером `archiv_tracker`.

## Темы и проверка релевантности

Этот раздел описывает archive.org и arXiv. Для NUMDAM правила BM25 приведены ниже.

Тема — строка из `config.yaml` или из боковой панели, по одной фразе на строку. Фраза режется на слова по пробелам и дефисам. «medical multi-agent» становится словами `medical`, `multi`, `agent`. Порядок слов не важен: подойдёт заголовок, где эти слова стоят в другом порядке.

Запись проходит, если **все** слова одной темы нашлись в тексте. Сравнение без учёта регистра.

- Короткая аббревиатура (все буквы заглавные и их не больше пяти, либо в слове меньше четырёх букв и цифр) ищется только как целое слово. `RAG` не срабатывает внутри `storage` или `fragment`.
- Более длинное слово совпадает и как префикс: `agent` находит `agents` и `agentic`.

Поля проверяются так. Сначала заголовок и аннотация вместе: слова темы могут лежать в разных полях. Для arXiv этого достаточно, страницу препринта валидатор не скачивает. Для archive.org, если в заголовке и описании темы нет, загружается страница `https://archive.org/details/<identifier>`.

Запрос к самому API устроен так же по смыслу, но синтаксис у источников разный. archive.org ищет фразу целиком: `("medical multi-agent")`. arXiv собирает слова темы через `AND` и ищет их по всем полям (`all:`), с тем же правилом префикса.

## Диапазон дат

Этот диапазон действует на archive.org и arXiv. У NUMDAM отдельный фильтр по году публикации, по умолчанию «Все годы»; общая «Неделя» к нему не применяется.

Границы включительные: и день «с», и день «по» входят в выборку.

| Режим | Границы |
| --- | --- |
| Неделя | сегодня минус 7 дней … сегодня |
| Месяц | то же число месяц назад … сегодня; если такого числа нет, берётся последний день месяца |
| Произвольный | две даты «С» и «По»; если «С» позже «По», запуск в панели блокируется |

В панели по умолчанию выбрана неделя. Планировщик и прямой вызов агентов без дат тоже берут неделю.

archive.org добавляет к запросу `publicdate:[ГГГГ-ММ-ДД TO ГГГГ-ММ-ДД]`. API разворачивает эти даты на полные сутки, поэтому конечный день входит целиком. Сортировка — по `publicdate` по убыванию.

arXiv добавляет `submittedDate:[ГГГГММДД0000 TO ГГГГММДД2359]` в GMT: это дата первой отправки препринта. Отдельный проход по `lastUpdatedDate` добирает новые версии, у которых в диапазон попала дата обновления, а не первой отправки. Между запросами к API выдерживается пауза 3 секунды. Ответ — Atom XML с `https://export.arxiv.org/api/query`.

## Что возвращает агент-источник

Общие поля записи: `source`, `identifier`, `title`, `url`, `abstract`.

Агент archive.org кладёт в `identifier` идентификатор archive.org, в `url` — страницу details, в `abstract` — поле `description`.

Агент arXiv кладёт в `identifier` строку вида `arxiv:<id>`, в `url` — страницу abs, и добавляет `authors`, `published`, `updated`. Резюме и почту этот агент не делает: он только возвращает записи скраперу.

## Панель

Запуск:

```bash
./run_ui.sh
```

Скрипт поднимает Streamlit из `.venv` командой `streamlit run streamlit_app.py`. Адрес по умолчанию — `http://localhost:8501`.

Боковая панель задаёт параметры одного сеанса. Темы и список источников в начале сеанса читаются из `config.yaml`, дальнейшие правки в панели в файл не записываются.

- Темы, по одной в строке.
- Подключённые источники: `archive.org`, `arxiv.org` и `NUMDAM`. Пустой список блокирует кнопку запуска.
- Диапазон дат: неделя, месяц или произвольный.
- Количество результатов с каждого источника (5–100, шаг 5, старт 20). Для NUMDAM это top-k по BM25, а не размер индекса.
- Число предложений в резюме (1–10, старт 3) и лимит текста страницы (500–10000 символов, старт 2000).
- Пропуск уже просмотренных и запись в историю. В панели оба флажка по умолчанию выключены, чтобы один и тот же поиск можно было повторить. Планировщик, наоборот, пропускает историю и сохраняет найденное.
- Очистка `history.json`.
- Почта в панели выключена и недоступна для включения. Получатель показывается из конфигурации.
- Интервал планировщика только отображается; меняется он в `config.yaml`.

Вкладка «Поиск» запускает один цикл и показывает счётчики, карточки и таблицу. В карточке есть источник, идентификатор, ссылка, резюме и статус. Вкладка «Схема агентов» встраивает `diagr/agents.html`. Внизу поиска раскрывается хвост `main.log` (последние 20 строк).

## История

`history.json` хранит идентификаторы уже принятых записей. Размер списка ограничен `history_size` (по умолчанию 1000): остаются последние. Скрапер дописывает идентификатор после того, как валидатор запись принял, и только если сохранение истории включено.

Идентификатор archive.org — это identifier архива. arXiv использует префикс `arxiv:`, NUMDAM — `numdam:`. Для NUMDAM история и фильтры применяются до окончательного выбора top-k, сохраняя порядок BM25.

## Почта и планировщик

Планировщик:

```bash
./run_agents.sh
```

Это `python main.py` из `.venv`. APScheduler ставит `process_items` на повтор каждые `check_interval_seconds` секунд (по умолчанию 3600). Остановка — `Ctrl+C`. Если APScheduler не установлен, срабатывает запасной режим: один цикл сразу и процесс завершается.

Письмо уходит, только когда цикл вызван с отправкой и в конфигурации `send_email: true`, а блок `email` заполнен. Тема письма: «Новая публикация (источник): название». В теле — ссылка и резюме. Ошибка SMTP пишется в журнал, остальные публикации цикла продолжают обрабатываться.

## NUMDAM: индекс, синхронизация и поиск BM25

### Быстрый запуск в Windows

Из PowerShell:

```powershell
Set-Location -LiteralPath 'D:\Agent_Space\projects\MAS\Лекция_3'
& '.\.venv\Scripts\python.exe' -m streamlit run streamlit_app.py --server.address 127.0.0.1 --server.port 8501
```

Или запустите `run_ui.cmd`. Панель доступна по адресу [http://127.0.0.1:8501](http://127.0.0.1:8501).

1. На вкладке «Индекс NUMDAM» нажмите «Синхронизировать метаданные». По умолчанию пробный импорт ограничен двумя страницами API: статьями и годами публикаций. Это **частичный индекс**, а не весь каталог.
2. Для полного импорта снимите «Ограниченный импорт для проверки» и запустите синхронизацию. Поток продолжит сохранённую позицию. В панели видны прогресс, количество статей, отсутствие аннотаций/годов и время последней полностью успешной синхронизации.
3. Выберите источник NUMDAM, введите, например, `partition` или `graph`, оставьте «Все годы NUMDAM» и нажмите поиск. Для аннотаций на французском полезны французские термины, например `graphe`.
4. При необходимости ограничьте годы. Флажок «Включать статьи с неизвестным годом» явно определяет, попадут ли они в результаты даже при выбранном диапазоне.

Синхронизация идёт в фоновом потоке. Кнопка остановки сохраняет текущую страницу и завершает работу после неё; сетевой запрос может ещё ждать ответа или ограниченного повтора. Поиск возможен по уже сохранённым данным. Сбой сети сохраняет завершённые страницы и показывает ошибку. Запуск после перезапуска приложения продолжает импорт. Одновременные импорты одной базы блокируются файловой блокировкой.

CLI из каталога проекта:

```powershell
# Пробный импорт; последующий такой же вызов продолжит загрузку.
& '.\.venv\Scripts\python.exe' numdam_agent.py sync --max-pages 2
# Полный импорт / продолжение; после полного импорта — инкрементальное обновление.
& '.\.venv\Scripts\python.exe' numdam_agent.py sync
# Заново пройти весь каталог, сохранив уже полученные записи.
& '.\.venv\Scripts\python.exe' numdam_agent.py sync --full
# Состояние и автономный поиск без обращения к NUMDAM и без суммаризации.
& '.\.venv\Scripts\python.exe' numdam_agent.py status
& '.\.venv\Scripts\python.exe' numdam_agent.py search 'graph partition' --rows 10
& '.\.venv\Scripts\python.exe' numdam_agent.py search 'partition' --year-from 1980 --year-to 2000 --exclude-unknown-year
```

Другую базу можно выбрать глобальным параметром `--db`, перед подкомандой: `numdam_agent.py --db data/test.sqlite3 status`.

### Данные и ограничения покрытия

Используется официальный [OAI-PMH NUMDAM](https://numdam.org/metadata/) по адресу `https://www.numdam.org/oai`. Перед импортом проверяются `Identify` и `ListMetadataFormats`. OAI-PMH выгружает метаданные; поисковый текст этому API не передаётся. HTML и PDF для NUMDAM не загружаются ни при импорте, ни при валидации, ни для резюме.

Основные записи загружаются в формате `eudml-article2`: названия и их переводы, авторы, аннотации и их переводы, журнал, язык, ключевые слова, MSC и ссылка — когда эти данные присутствуют. В проверенных реальных записях год отсутствовал в этом формате, поэтому вторым пагинируемым потоком загружается `oai_dc`; дата публикации объединяется по идентификатору. Независимые контрольные точки обоих потоков позволяют продолжать загрузку без запроса даты отдельно для каждой статьи. Неизвестные данные не восстанавливаются из имени идентификатора. Если известен только год, `published` содержит год без выдуманного месяца и дня.

`oai_datestamp` — дата изменения метаданных, а не публикации. Для обновления используется зафиксированная граница OAI с перекрытием в один день и upsert по идентификатору. Записи, поисковый индекс и контрольная точка страницы сохраняются одной транзакцией. Успех фиксируется только после завершения обоих потоков. Если `resumptionToken` протух, соответствующий поток начинается заново с теми же временными границами; дубликаты не создаются.

Удаляющие OAI-записи поддерживаются. Однако 29.10.2026 NUMDAM сообщал `deletedRecord=no`: сервер не гарантирует выдачу отметок удаления. Исчезновение записи без такой отметки автоматически не обнаруживается, в том числе при `--full`. Полный индекс означает успешно завершённый обход доступных метаданных, а не гарантированную полноту аннотаций или полных текстов.

При сетевой проверке загружены только первые 100 статей: у 83 есть аннотации, у 17 их нет; годы получены из Dublin Core. Сервер сообщал о 72 533 записях формата `eudml-article2` на момент проверки. Эти числа описывают конкретную проверку, а не постоянные свойства каталога. База `data/numdam.sqlite3`, её WAL-файлы и блокировка исключены из Git.

### Правила ранжирования

SQLite FTS5 считает настоящий `bm25()` по всему **сохранённому** корпусу. Настройка `rows` ограничивает выдачу, а не корпус. Значение в выдаче — `bm25_score = -bm25(...)`: больше означает более высокое место для данного запроса; это не вероятность и не процент. При равных оценках порядок определяется `identifier`.

В `config.yaml`:

```yaml
numdam:
  database: data/numdam.sqlite3
  bm25_weights:
    title: 5.0
    abstract: 1.0
    keywords: 2.0
```

Запрос и документы обрабатываются одним токенизатором FTS5 `unicode61 remove_diacritics 2`. Слова объединяются через OR; кавычки, дефисы и знаки не становятся операторами MATCH. Пустой запрос возвращает пустую выдачу, лимит — 256 разных терминов. Поиск лексический: без embeddings, семантики, автоматического перевода и морфологии. MSC хранится в метаданных, но в три поисковых поля автоматически не добавляется. Статистика BM25 меняется по мере наполнения базы.

Фильтр годов и исключение истории применяются до top-k. Выдача NUMDAM не проходит старую проверку «все слова должны присутствовать». Суммаризатор обрабатывает только найденные аннотации; короткие аннотации не вызывают HTML-fallback. Статья без аннотации выводится со статусом «Аннотация отсутствует — резюме недоступно». Для полностью локальных резюме выберите Sumy. На новой установке ему могут понадобиться данные NLTK:

```powershell
& '.\.venv\Scripts\python.exe' -m nltk.downloader -d .venv/nltk_data punkt punkt_tab
```

Отсутствие этих данных или недоступность провайдера не мешает CLI-поиску и не удаляет статьи из выдачи панели.

### Проверки

```powershell
& '.\.venv\Scripts\python.exe' -m unittest discover -s tests -v
```

Проверки работают без внешней сети и на временных базах: реальные XML-фикстуры, ошибки OAI при HTTP 200, Retry-After, пагинация и продолжение, транзакции, дедупликация/удаления, BM25 и веса, Unicode, история/годы до top-k, запуск поиска отдельным процессом, отсутствие HTML/PDF-запросов, сохранение выдачи при ошибке резюме и интерфейс Streamlit. Действия с почтой и существующими источниками в тестах подменены локальными ответами; реальные сервисы не опрашиваются.

## Новый источник

Агент-источник — отдельный модуль с константами `SOURCE_ID`, `SOURCE_NAME` и функцией `fetch(topics, rows=20, date_from=None, date_to=None)`. Функция возвращает список словарей с полями `source`, `identifier`, `title`, `url`, `abstract`. Модуль регистрируется в словаре `SOURCES` в `scraper.py`. После этого источник появляется в панели и его можно указать в `config.yaml`.
